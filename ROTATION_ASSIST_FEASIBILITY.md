# Подсказки ротации: проверка API

Проверено 2026-09-07 по интерфейсу Blizzard **12.1.0 (69587)**,
commit `8ea15b61e45c0ed4eba01439c90757f86eb78d34`. Это исследование API;
новый помощник ротации в MythicBoost пока не реализован и не проверен в игре.

## Вывод

Можно сделать одну крупную карточку следующей рекомендуемой способности
с реальным назначением клавиши: например `Shift + Q`, `Mouse 4`, `Ctrl + Mouse 5`.
Для основного режима не нужна собственная записанная ротация каждого класса:
следующее заклинание выбирает штатный помощник Blizzard. Аддон представляет
его рекомендацию и привязку; способность по-прежнему нажимает игрок.

В бою не исчезает весь API. Ограничения относятся к обработке закрытых
значений и защищённым действиям. Статическая информация, разрешённые
интерфейсы отображения и штатная рекомендация имеют отдельные контракты.

## Подтверждённые интерфейсы

- `C_AssistedCombat.IsAvailable()` сообщает доступность помощника и причину отказа.
- `C_AssistedCombat.GetNextCastSpell(checkForVisibleButton)` возвращает следующий
  рекомендуемый spell ID. В описании 12.1.0 результат не помечен как secret.
  Штатный `AssistedCombatManager:OnUpdate` вызывает функцию, сравнивает ID
  и обновляет подсветку; обновление продолжается во время боя.
- `C_AssistedCombat.GetRotationSpells()` даёт набор заклинаний помощника.
  Штатный код хранит его как множество: это **не предсказанная очередь**
  следующих действий. Нельзя честно рисовать из него «следующие три кнопки».
- `C_ActionBar.FindSpellActionButtons(baseSpellID)` находит слоты с заклинанием.
  Для заменённых заклинаний API требует базовый ID.
- Штатная кнопка использует `GetBindingKey(bindingAction)` с запасным
  `GetBindingKey("CLICK " .. buttonName .. ":LeftButton")`, затем `GetBindingText`.
  Так можно показывать клавиши, модификаторы и назначенные в WoW кнопки мыши.
  Переназначение боковой кнопки на клавишу в драйвере мыши не раскрывает
  физическую кнопку аддону; в таком случае виден только бинд WoW.

## Ограничения и устройство будущего модуля

Общий модуль подходит специализациям, для которых доступен Assisted Combat.
Он предлагает DPS-действия; это не самостоятельный выбор лечения или защиты.
Blizzard описывает рекомендацию как помощь в освоении специализации и учитывает
ресурсы и ситуацию. Гарантировать максимальный возможный DPS по ней нельзя.
[Описание Blizzard](https://worldofwarcraft.blizzard.com/en-us/news/24205457).

Предлагаемый основной режим: одна карточка со способностью, названием и крупной
привязкой; состояние «нет назначения» для отсутствующей клавиши. Обновлять карту
привязок при смене специализации, формы, панели и назначений. Обрабатывать
заменённые способности и макросы отдельно, не угадывать неоднозначные макросы
или назначения сторонних click-cast аддонов. Не менять пользовательские бинды.
Частоту обновления ограничить, использовать одну заранее созданную карточку;
скрывать её при недоступности или закрытом результате, без восстановления
закрытых данных обходными путями.

Записанный opener или последовательность по таймеру возможны как отдельный
учебный режим с ручным запуском/паузой/сбросом. Без подтверждения попаданий,
ресурсов, прерываний, проков и фактических кастов такая последовательность
рассинхронизируется; её нельзя выдавать за адаптивную оптимальную ротацию.
Пакеты для классов здесь нужны только для самих записанных учебных сценариев.

До выпуска модуля нужна проверка непосредственно в клиенте: вне боя и на
манекене, с клавиатурой и мышью, сменой формы/специализации/макроса, отсутствующим
биндом, выключенным Assisted Highlight и недоступной рекомендацией. Mock-тесты
не докажут доступность API или отсутствие taint в реальном клиенте.
