# Покрытие возможностей Shortlist в MythicBoost 2.4.111

Сравнение с установленным Shortlist v0.6.1-beta1. Реализация MythicBoost
самостоятельная; Shortlist не является зависимостью. Область — Mythic+ и текущие рейды.

| Возможность Shortlist | MythicBoost |
| --- | --- |
| Серверный поиск и диапазон ключей | Ввод в оригинальное поле Blizzard из нашего окна, сохранение текста при обновлении |
| Сохранённые представления | Убраны по запросу пользователя |
| Уровень, подземелья, рейтинг, опыт | Основные фильтры и сезонные карточки |
| Возраст, размер, близость к своему рейтингу | Панель дополнительных условий убрана; возраст и размер доступны в боковой панели рейдов |
| Места для ролей всей пати, Bloodlust, боевой рес | Существующие фильтры состава |
| Повтор своего класса, друзья, доступность заявки | Отдельная панель убрана; рейдовые условия остаются в боковой панели |
| Сортировка | Всегда по приоритету, активные заявки закреплены сверху |
| Состав группы, опыт и ключи | Классы в строке, подробности по участникам при наведении, личные рекорды на карточках |
| Apply / Cancel / роли / комментарий | Один клик, роль из специализации, отмена; Shift+клик для штатного комментария |
| Активные заявки | Всегда сверху, включая заявки за пределами текущей выдачи |
| Чёрный список | Метки лидеров и их влияние на выдачу удалены |
| Избранное | Убрано |
| История заявок | Отдельный журнал убран из интерфейса |
| Show all | Секция с причинами отсева всегда остаётся под подходящими группами |
| Плотная таблица | Постоянная высота строк и прокрутка |
| Создание объявления и кандидаты | Существующие «Собрать пати», карточки кандидатов и открытие штатной формы объявления |
| История совместных ключей, аналитика | Существующие напарники, результаты ключей, оценки, статистика талантов |

Рейдовый режим добавляет текущие рейды, сложности, свежую группу, ограничение
числа убитых боссов, выбор «жив/убит» для отдельных боссов и сравнение прогресса
с собственным сохранением. Общий редактор добавляет стили, минимальные количества
ролей, исключение специализаций, поиск нужных ролей, языки, свой сервер/фракцию,
автоприём и отсутствие игроков с отметкой покидания группы.

Не перенесены произвольные логические выражения состава, регионы серверов,
статистика конверсии заявок и свободная раскладка столбцов Shortlist.
Собственная аналитика MythicBoost сохраняется.

Диапазон вводится в оригинальный EditBox Blizzard из нашего окна. После
завершённого запроса N-N неизвестные уровни отображаются как запрошенный +N;
доступный уровень объявления имеет приоритет. У диапазона N-M нет общего +N.

## Проверка в игре

После установки выполнить `/reload`. В `/mb`: ввести `10-10`, обновить дважды;
убедиться, что текст виден во время ввода и диапазон остаётся после обновления.
Проверить «Доп. фильтр»: доступны только состав, стили, специализации и языки.
Отправить и отменить одну заявку своим кликом; она должна появиться сверху
без дублирования, а после отмены вернуться в общий порядок. Проверить восстановление
штатного окна после Escape, закрытия MythicBoost и начала боя.

Проверить с включённым Shortlist autoOpen и без него: ввод не должен открывать
Shortlist вместо MythicBoost. Его настройка до и после действия должна совпадать.
Обе кнопки создания должны сразу открыть форму текущего камня с «Серьёзным»,
сохранить черновик при повторном входе и закрыть форму при штатном «Назад».
В режиме рейдов проверить 14/15/16, выбор рейда, босса, свежесть, собственное
сохранение и заявку в группу из более пяти человек. Неполные данные боссов
показываются как неизвестные, а не как подтверждённые 0 убийств.

В следующем ключе со включённым штатным счётчиком проверить DPS/HPS после боя
и завершения. Старые записи без длительности автоматически не восстанавливаются.
Длительность читается из таблицы сессии или через
[GetSessionDurationSeconds в документации Blizzard](https://github.com/Gethe/wow-ui-source/blob/live/Interface/AddOns/Blizzard_APIDocumentationGenerated/DamageMeterDocumentation.lua).
Это время сессии счётчика, а не весь таймер прохождения.

Локальные тесты проверяют данные и UI-контракты; ограничения protected/taint
окончательно проверяются в работающем клиенте.
