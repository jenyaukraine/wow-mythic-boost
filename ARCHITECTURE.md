# MythicBoost: правила безопасных изменений

Этот файл — контракт для следующих ручных и сгенерированных правок. Цель не в
том, чтобы запрещать развитие аддона, а в том, чтобы ошибка одного API-вызова
не размножалась по нескольким модулям.

## Порядок слоёв

1. `Localization.lua` создаёт только локализацию.
2. `Contracts.lua` владеет secret-safe типами, лимитами памяти и нестабильными
   Blizzard API.
3. `Core.lua` владеет БД, жизненным циклом модулей и общими событиями.
4. `UI.lua` владеет визуальными конструкторами.
5. `Modules/*.lua` реализуют пользовательские сценарии через эти слои.

Порядок закреплён в TOC и проверяется `Tools/CheckArchitecture.py`.

## Blizzard API

- Модули не вызывают напрямую API завершения/активного Mythic+ и состояния
  LFG-заявок. Новая форма данных сначала нормализуется в `JP.API`.
- Контракт возвращает таблицы с именованными полями. Позиционные tuple-значения
  не должны проходить дальше `Contracts.lua`.
- `false` является данными. Для необязательного boolean используется
  `JP.SafeOptionalBoolean`, а не выражение `value and x or nil`.
- Любое значение из LFG сначала проходит `JP.Safe*`/`JP.IsSecret`.
- Защищённые Apply/Cancel/Search вызываются только непосредственно из клика
  игрока; таймер не переносит hardware event.

## Память и SavedVariables

- Все постоянные лимиты находятся в `JP.Limits`. Магические копии в модулях
  запрещены.
- Любая новая коллекция в SavedVariables обязана иметь TTL или количественный
  предел, очистку повреждённых записей и тест переполнения.
- В историю пишутся компактные агрегаты, не сырой combat log.

## События и UI

- Частые события (`COMBAT_LOG_EVENT_UNFILTERED`, `OnUpdate`) регистрируются
  только на время активной функции и обязательно снимаются в `Disable`.
- `Create` не должен повторно создавать фреймы. `Enable` и `Disable` должны
  выдерживать повторный вызов.
- Новые панели создаются через `JP.UI`, а не собственной копией стилей.
- Заброшенный код удаляется или хранится в истории Git, но не лежит рядом с
  рабочими модулями как ложный пример для следующей генерации.

## Перед релизом

```powershell
python Tools/CheckArchitecture.py
python Tools/TestMythicBoost.py
powershell -NoProfile -ExecutionPolicy Bypass -File Tools/BuildRelease.ps1
```

Сборка обязана падать до создания ZIP, если архитектурный контракт нарушен,
и повторно проверяет уже созданный архив через `Tools/VerifyRelease.py`.
